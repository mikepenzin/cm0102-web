# Issue 132: the remaining known crash sites of the original

Date: 2026-11-13 (0.8.0 slice 17). Exe: `clean-3968/cm0102.exe` (3.9.68). Memory = file offset + 0x400000.
Earlier research: `2026-10-16-crash-fixes.md` (the 0.5.0 guards). The full notes per site, with every caller and
what was checked, are outside the repo in `run-logs/0.8.0-s817/site-*.md`.

The port maps guest page 0. A NULL read gives zeros and a NULL write succeeds, so where the original stops the port
goes on with wrong data. Each site now logs its first hit in a run to stderr: `recomp: crash site <addr> reached,
day <d>, year <y> (issue 132)` (`rt_crash_site`, `src/recomp_rt/win/original_faults.c`). The run set's logs then show
whether the port reaches a site.

## virtual_staff.cpp 195

- The box shows when a fixture club still has fewer than 15 players after the top-up `VIRTUAL_STAFF::top_up_club_squad`
  0x90dae0 (count 0x90d43a..0x90d469, line 0xc3 pushed at 0x90d494). The function then calls `release_fixture`
  0x90d6b0 and itself with no_check 1 (0x90d4d1, 0x90d4dc).
- The top-up gives no players to a club with no nation (club +0x53 NULL, test 0x90db33). The match set-up then reads
  the away club's nation in 0x85d8a0 (`mov edx,[eax+0x53]` 0x85d8b5, `movsx eax,[edx+0x7e]` 0x85d8b8). That is the
  crash of an outside patch.
- Clean data: the id pass (0x5315d6..0x531605) gives 1579 clubs a NULL nation. 19 of them are in a division
  (Norwegian B sides in 317 to 320 and 346, Barcelona C and Real Madrid C in 98), all with 0 players. Every table fill
  and entrant pick for those divisions tests +0x53 first (0x792a22, 0x78f9b9, 0x78fa5d, 0x8534f1, 0x8535b7, 0x853686,
  0x84d952, 0x84db9f, 0x84ddd9). So no club with no nation enters a fixture in a base game.
- The box has a second cause, a short under-21 side (the top-up gives nothing when nation +0x88, the nation's staff
  count, is above 500, 0x90dd5d). In clean data each such nation has at least 38 players born in 1981 or later. This
  path never reaches 0x85d8b8.
- Season data reached the box in 0.6.0 by five routes, each fixed at its cause (commits 4ac8a7cb, 5d9c102f, 622fd3ac
  and the under-21 pick). No run log after those fixes shows the box.
- The 0.5.0 guard at 0x85d8b8 stays, now with the log line. An outside patch that removes the box only hides it.

## transfer_manager.cpp with no player record

- 0x84aeb0 (thiscall club, staff; ret 8) clears the bid markers of a staff member in a club's list of 40 entries. It
  reads the club id at 0x84aebb.
- Its 34 callers are 17 pairs in transfer_manager.cpp (for example `reject_transfer_offer` 0x8bf680, calls 0x8bf774
  and 0x8bf7ae). The second call of each pair runs over the part-exchange players [offer+4] with the selling club,
  which is 0 when the offer player has no contract (`get_contract` 0x4cf5a0, for example `xor ebx,ebx` 0x8bf75a).
- A player with no club is a case the code expects: `process_due_offer` sends an offer with no selling club on to
  `accept_transfer_bid` (0x8c6455..0x8c6a45), which tests for it (0x8c012b, 0x8c0194). Only the part-exchange loops
  have no test. With no selling club there is no bid list to clear, so the 0.5.0 exit to 0x84aef1 gives the result
  the code means. It changes nothing in a game that does not reach it.
- A path that leaves a part-exchange offer open for a player with no contract: the human "terminate contract" action
  0x4e5610 removes the contract (0x4e567f) and does not cancel the offers. The AI paths cancel or wait first
  (0x4c9cfb, 0x8c1a5a, 0x8cd919, 0x7a5b02). To cancel the offers there would change the game when a human releases a
  player under offer: a rule change, not done here.

## The Dutch top league

- `HolFirst::set_club_progress` 0x5f73d0 is slot +0x68 of the HolFirst vtable 0x96b86c. For play-off stage 4 or 5 and a
  club of the Eredivisie ([0x9cf568]) it looks the club up in the Eredivisie stats (`Comp_Stats::find_club_entry`
  0x4a4850, call 0x5f74a7) and writes bytes +0x73..+0x75 through the result (0x5f74ec, 0x5f74fe). An outside patch
  returns when the result is 0. The first lookup (0x5f73e1) is not checked either.
- The only path with stage 4 or 5 is 0x685473 on a play-off group, forwarded by `Comp::set_club_progress` 0x48e380.
  The groups hold the two Eredivisie clubs of status 2 (0x5f68ad), which played the whole season. The table reset
  (0x5f8653), the club moves (0x5f8623) and the deletion of the groups (0x5f87af) all run in
  `HolPrm::start_new_season`. `season_ned_second.c` moves clubs only inside that call.
- I don't know the cause, and I found no path to a NULL. One open point: the loop at 0x5f68a3 has no bound on the row
  index. Both lookups now log a NULL result (`tools/recomp/original_faults.py`, 0x5f73e6 and 0x5f74ac). The game goes
  on as before.

## Argentine Second Division average points (1 August)

- Outside patches change `jle` to `jmp` at 0x409d7e.
  The function is `ArgSecond::update_relegation_averages` 0x409c20 (vtable 0x9673d8 slot +0x34), not 0x4093f0 as
  `2026-10-16-crash-fixes.md` section 1b says.
- The loop over the stages [this+0xc][i], i < [this+0x30], keeps i in eax (0x409d41). The club search reuses eax
  (0x409d5b, 0x409d77, 0x409d9e) and nothing saves it, so the next stage index is the averages index of the last club
  found, plus 1 (0x409e24). Inference: the source used one variable for both loops.
- Stages 0 to 2 are `League_Stage` zones (ctor 0x68b100, vtable 0x96d0f0, calls 0x408417, 0x4084bf, 0x408567).
  Once the promotion play-offs exist ([this+0x30] = 5 at 0x408ca8) the loop can reach stages 3 and 4, which are
  `Cup_Stage` objects of 0xb2 bytes (vtable 0x969468, ctor 0x522e00, stores 0x408873, 0x408a67). The ctor sets the club
  count +0x3e from its argument (0x522f38) and only a byte at +0xb1 (0x522e8b). When the jump lands on one, the loop
  reads the dword at +0xb1 (that byte and 3 bytes after the object) as a table (0x409d5e) and goes through it
  (0x409d80, 0x409d85). Inference: that pointer is junk and the original crashes, unless the heap bytes happen to form
  a readable address. The callers then are the season-end call 0x4068f9 and the Average Points tab 0x4950e8. Clean
  data is enough.
- Fix (`tools/recomp/crashguards.py`, 0x409e25): the loop ends at the first stage that is not a `League_Stage`. A loop
  that reads only zones runs as before. Test: `tests/recomp/test_crashguards.py` (three cases against Unicorn).
- The register reuse also means the original adds the points of a random subset of the three zones. To add all
  three would change every game with Argentina: a rule change, not done here. An outside patch adds only zone 0.
- `ArgPrm::update_relegation_averages` 0x406570 (first division) reads only stage 1 and keeps its counter: no fault.

## Match engine error 1225

- The box is "match_man..cpp 1225" (file 0xa15da4 at 0x6dd3d9, line 0x4c9 at 0x6dd3f4). `MATCH_MAN::pick_team`
  0x6dbc50 finds one staff twice in its pick (0x6dd3c1). An outside patch removes the box and the match plays with the
  duplicate.
- Cause (open item 187): `CONTRACT_MANAGER::toggle_squad_placement` 0x4cbd20 moves a one-contract player to the linked
  side (0x4cc03d..0x4cc091) without setting bit 0x40 of the contract +0x35, which `get_squad_placement` 0x4cbb60 reads
  (0x4cbcb8). The byte was never set (`STAFF_CONTRACT` 0x85e410, `operator=` 0x4cc810), so each squad assessment
  added the player to the B side again. Fixed since 0.6.2 (`rt_squad_move_set`, original_faults.py 0x4cc03d, group
  squad_moves). No log of any run after it shows the box.
